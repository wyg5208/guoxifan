# 07 · 开发计划与里程碑

## 1. 总体节奏

按 **4 个阶段 + 1 次上线后迭代** 推进。以"单人 + AI 辅助"为基准估算；若有 2 人协作，M2/M3 可并行，总工期压缩约 35%。

| 阶段 | 周期 | 目标 | 可交付状态 |
| --- | --- | --- | --- |
| M0 地基 | 第 1 周 | 工程骨架、账号体系、部署通路跑通 | 线上能登录，能改站点名 |
| M1 内容 | 第 2–3 周 | 照片 / 文章 / 短文 / 互动 | 可上真实内容，给家人试用 |
| M2 人物 | 第 4 周 | 村民、家庭、名片、村史时间轴 | "村子的人"立起来 |
| M3 社交 | 第 5–6 周 | 聊天室、私聊、通知、审核 | 内部完整可用 |
| M4 打磨 | 第 7 周 | UI 精修、PWA、性能、后台补全 | 正式对外发布 |
| P1 增强 | 上线后 | 家庭树、搜索优化、口述历史 | 持续迭代 |

> 时间可压缩的秘诀：**先上线"照片 + 文章"，聊天室后置**。村民最先想看的是老照片，聊天室在拆迁既成事实后热度会逐步下降，但它是留住人的关键，不能砍。

- [ ] `scripts/seed.py`：写入 20 项 `site_settings` + 超管账号
- [ ] 认证：`/auth/register` `/login` `/refresh` `/logout` `/me`
- [ ] 注册模式三档（`open` / `invite` / `closed`）+ 审核开关 + 邀请码校验与计次
- [ ] 审核接口：`/admin/users/{id}/approve|reject` + 批量通过
- [ ] 统一异常处理 `AppError` + 响应包装 + 请求日志中间件
- [ ] `GET /site/config`、`GET /healthz`
- [ ] `POST /admin/settings` 基础配置 CRUD + 审计

**前端**
- [ ] Vite + TS + Tailwind 4 + shadcn 初始化，配置路径别名与代理
- [ ] 设计 token（CSS 变量）、字体子集化脚本、基础 `ui/` 组件皮
- [ ] `api/client.ts`：token 注入、401 刷新、错误 toast
- [ ] 路由骨架 + `SiteLayout` / `AdminLayout`
- [ ] 登录 / 注册页（邀请码按 `reg_mode` 动态必填/选填/隐藏）+ pending 提示条
- [ ] 站点配置 Hook（`useSiteConfig`）+ 全局页头页脚

**运维**
- [ ] GitHub 仓库 + Vercel 项目（Preview 部署可用，先用 vercel.app 默认域名）

**验收**：手机打开 Vercel 预览链接能自助注册（无需邀请码）、管理员能在后台一键审核通过、能改站点标题并立刻生效；切到 `invite` 模式后注册页立刻要邀请码。

## 3. 每日工作方式建议

```
早上 30 分钟：看昨日数据 / 处理待审内容 / 回复留言
上午 3 小时  ：写功能（先写接口再写页面，单个垂直切片做完再下一个）
下午 2 小时  ：自测 + 修 bug + 提交（每天至少合一次 main，保持可部署）
晚上 30 分钟：录入真实数据（这一步不要留到最后，边做边录）
```

**每个功能切片的完成定义（DoD）**
1. 接口有 OpenAPI 文档与错误码；2. 前端有空/错/加载三态；3. 移动端可用；
4. 权限已校验（含越权测试）；5. 有真实数据验证过；6. 已合并到 main 并通过 Vercel 预览。

## 5. 验收标准（总）

### 功能
- 所有 P0 需求可完整走通，无阻断性缺陷。
- 权限矩阵逐项验证：游客 / pending / member / editor / admin / super_admin 各角色行为正确。
- 上传：图片（含 HEIC）、视频、文件三类均成功；失败有明确提示与重试。

### 质量
| 指标 | 标准 |
| --- | --- |
| 单元测试 | 认证、权限、消息 seq、计数 4 个核心模块覆盖 |
| 接口 P95 | < 500ms（不含上传与转码） |
| 前端 Lighthouse（移动） | Performance ≥ 90，Accessibility ≥ 90，Best Practices ≥ 90 |
| 兼容 | iOS Safari 15+、Chrome Android 100+、Edge/Chrome 桌面 |
| 可用性 | 连续运行 7 天无崩溃、无内存泄漏（观察 RSS） |

### 数据
- 全量导出 zip 能在另一台机器用 Python 脚本还原并启动服务。
- 备份保留 30 天，恢复演练通过并记录耗时。

## 6. 风险登记表

| # | 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- | --- |
| R1 | 家里宽带无公网 IP / 80 被封 | 高 | 后端无法对外 | 提前确认；备选：云服务器（轻量）+ 备案，或 Cloudflare Tunnel（免费，免公网 IP） |
| R2 | 未备案导致域名被拦 | 低 | 上线延期 | 备案与开发并行；阶段 A/B 用 vercel.app + Cloudflare Tunnel，备案通过后改环境变量切换 |
| R3 | 老照片质量差/扫描件巨大 | 高 | 上传失败、存储爆 | 前端压缩 + 后端分片 + 提供"微信发给我，我来传"的人工兜底 |
| R4 | 长辈不会用、注册转化低 | 高 | 活跃度不足 | 年轻人代注册 + 邀请码；名片可无账号；PWA 手把手教装 |
| R5 | 聊天室变成吵架场所 | 中 | 情感伤害、村民流失 | 实名村民 + 管理员禁言 + 敏感词；先发后审但保留一键转审 |
| R6 | 单人开发周期失控 | 中 | 迟迟不能上线 | 严格按 M0–M4 排序，M1 结束就对外试运行，功能不齐但内容先上 |
| R7 | 服务器/域名到期导致数据消失 | 中 | 项目彻底丢失 | 日历提醒提前 60 天 + 异地备份 + 域名续费 10 年 |
| R8 | 隐私争议（未授权肖像/住址） | 中 | 有人要求删除 | 提供"申请下架"入口 + 隐私说明 + 已故者信息需家属同意 |
| R9 | SQLite 写锁导致报错 | 低 | 偶发 500 | WAL + busy_timeout + 监控；必要时迁 PG |
| R10 | Vercel 国内访问慢 | 中 | 长辈打不开 | 备案域名 + 备用前端部署在同机房，切换只需改 DNS |

## 8. 上线后 90 天运营建议

1. **每周固定动作**：上传 1 个主题相册（如"村小学""打谷场""婚礼"），发 1 篇短文，置顶 1 条村务通知。
2. **每月一次"口述"**：采访一位老人，录音 + 整理成文章，是站内最有价值的内容。
3. **节日节点**：春节做"云拜年"（聊天室置顶 + 首页横幅）；清明做"纪念先人"（已故村民专题）。
4. **季度回顾**：导出一次全量数据到本地硬盘，并检查备份可恢复性。
5. **观察指标**：注册转化、上传人数分布（若集中在 3 个人身上，说明门槛太高，要做引导）、聊天日活。
