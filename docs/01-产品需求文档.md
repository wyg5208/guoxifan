# 01 · 产品需求文档（PRD）

## 1. 项目背景与目标

村庄即将整体拆迁。物理空间消失之后，村民散居各地，"共同记忆"的载体同时消失。本项目要解决三件事：

1. **留存**：把散落在各家手机、相册、记忆里的照片、视频、故事集中到一个永不随拆迁消失的地方。
2. **连接**：拆迁后村民彼此失去日常接触面，需要一个"网上村口"继续说话、办事、拜年、报平安。
3. **传承**：让下一代知道"我们从哪来"——村史、老宅、长辈、方言、老物件。

**成功标准（上线 6 个月）**

| 指标 | 目标 |
| --- | --- |
| 注册村民 | ≥ 80% 常住户（按户统计） |
| 上传老照片 | ≥ 2000 张 |
| 文章/短文 | ≥ 150 篇 |
| 月活跃用户 | ≥ 40% 注册量 |
| 聊天室日活消息 | ≥ 30 条/日 |

---

## 2. 用户角色

| 角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| 游客（未登录） | 路过、外地子女、村外亲属 | 浏览照片、文章，感受氛围；不可发布 |
| 村民（member） | 注册并审核通过的本村人 | 上传、发布、评论、点赞、聊天、私聊 |
| 家族管理员 / 编辑（editor） | 热心、会写字的村民或返乡青年 | 整理相册、撰写村史、审核内容 |
| 管理员（admin） | 项目发起人 / 村委 | 用户审核、内容治理、站点配置 |
| 超级管理员（super_admin） | 技术维护者 | 全部权限 + 系统设置 + 数据导出 |

> 关键设计：**村民档案（Villager）与登录账号（User）解耦**。已故长辈、不会用手机的老人也能有完整名片与照片，但不占账号。

## 4. 详细需求

### M1 首页 / 记忆流

- 顶部大图 Hero：村庄全貌 + 村名 + 一句话介绍 + "村庄已拆迁 · 建于 ___ 年"等元信息（均由后台配置）。
- 记忆流（时间倒序瀑布流）：混合文章、短文、照片、视频，按内容权重（精选 > 新发布）排序。
- 侧栏/抽屉：最近上传、热门相册、活跃村民、我的收藏入口。
- 空状态设计：无内容时展示引导"上传第一张老照片"。
- 移动端：单列无限滚动；PC：2~4 列瀑布流（Masonry）。

### M2 照片墙 / 相册 / 视频馆

- **相册**：管理员/编辑创建相册（如"1980 年代的村小学"），可设封面、简介、年代、可见性（公开/仅村民）。
- **批量上传**：支持多选拖拽、手机相册直传、上传进度、断点重试；单张 ≤ 20MB。
- **自动处理**：EXIF 拍摄时间提取（用于按年代聚合）、方向纠正、生成 4 档尺寸（thumb 320 / small 640 / medium 1280 / original）、WebP 转换。
- **浏览**：灯箱大图 + 左右滑动 + 键盘方向键 + 缩放；显示拍摄时间、上传者、地点说明。
- **照片信息**：标题、说明、年代（如"1985 年前后"）、拍摄地、参与人标注（可关联 Villager）。
- **视频**：上传后转码为 HLS（720p/480p 自适应）+ MP4 兜底；浏览器不支持时降级 MP4；生成首帧封面。
- **交付能力**：点赞、收藏、评论、下载原图（可配置是否允许）、分享链接。
- **老照片修复/上色**：不影响 MVP，仅预留"原图 / 修复图"双版本字段。

### M3 文章 & 短文

- **文章**（长文）：富文本编辑器（Tiptap），支持标题、段落、图片、视频嵌入、引用、分隔线、图注。
- **短文**：类似朋友圈/微博的纯文本 + 最多 9 张图，限 2000 字。
- 草稿箱、定时发布、置顶、加精、归档。
- 分类与标签：分类（村史 / 人物 / 风俗 / 农事 / 已拆迁记录），标签自由。
- 阅读体验：目录锚点、阅读进度条、字号调节、夜间模式。
- 互动：点赞、收藏、评论（支持二级回复）、@提醒。

### M4 村史时间轴

- 横向/纵向时间轴，节点 = 年代 + 事件 + 配图 + 关联文章。
- 支持"公元前式"模糊年代表达（"解放前"、"60 年代末"），字段设计见数据库文档。
- 支持按分类筛选（大事记 / 建筑 / 生产 / 人物 / 风俗）。
- 后台可拖拽排序。

### M5 村民与家庭

**家庭（Family）**
- 字段：户主、门牌号、所在片区、老宅位置（经纬度或在地图图片上的相对坐标）、家庭简介、全家福、拆迁年份、现居地。
- 家庭详情页：成员列表（长辈→晚辈排序）、家庭相册、家庭故事、时间线。

**村民（Villager）**
- 名片卡片：头像/肖像、姓名、乳名/绰号、辈分（字辈）、生卒年月、职业/身份、家庭、在世状态、联系方式（隐藏/仅村民可见）、个人简介、代表照片。
- 关系：配偶、父母、子女（用于家庭树/族谱视图）。
- 已故村民：名片带特殊视觉样式（黑白/缎带），可设置纪念留言墙。
- 族人关系图（v1.1）：力导向图或树状图展示宗族关系，这是本项目最具情感价值的功能之一。

**村民之间私聊**
- 在村民名片页点击"私信"进入一对一会话。

### M6 聊天室

**房间类型**
| 类型 | 说明 |
| --- | --- |
| `hall` 全村大厅 | 唯一，所有登录村民可见可发言 |
| `group` 群聊 | 由管理员创建（如"三队老乡群"、"村委通知群"），可设置是否公开 |
| `direct` 私聊 | 一对一会话，按需创建 |

**消息类型**：文本、图片、视频、文件（≤ 100MB）、语音（v1.1）、系统消息、撤回提示。

**能力**
- WebSocket 实时收发，断线自动重连（指数退避）、重连后拉取断档消息（基于 `seq` 游标）。
- 历史消息分页（游标倒序），本地缓存最近 200 条。
- 已读回执（私聊）、@提及、消息引用回复、撤回（2 分钟内）、删除。
- 未读数角标、桌面通知（Notification API）、静音房间。
- 内容安全：敏感词过滤、举报、管理员可撤回/禁言/踢人。
- 移动端：输入框固定底部，`visualViewport` 适配键盘弹起；支持粘贴/拖拽上传。

### M7 个人中心

- 我的资料（头像、昵称、简介、绑定村民档案）、我的上传、我的收藏、我的点赞、我的评论、我的文章草稿。
- 通知中心：评论/回复/点赞/@/审核结果/系统公告。
- 账号安全：修改密码、退出登录、注销账号（内容保留、署名改为"已注销村民"）。

### M8 管理后台（`/admin`）

| 分组 | 功能 |
| --- | --- |
| 概览 | 关键指标卡片（用户数、内容数、存储占用、今日活跃）、最近待审、存储趋势图 |
| 站点配置 | 站点名称、Logo、站点简介、Hero 大图与文案、建村年份、拆迁日期、备案号、页脚、社交分享默认图、主题色；开关：注册模式（自助/邀请制/关闭）、自动通过审核、游客可见、评论开关、下载开关 |
| 用户与村民 | 待审核队列（批量通过/驳回）、角色分配、禁用/恢复、重置密码、邀请码生成（可设次数/有效期/是否免审核） |
| 家庭管理 | 增删改查、成员调整、地图坐标 |
| 内容管理 | 文章/短文/照片/视频列表、批量删除、加精置顶、审核队列 |
| 相册管理 | 相册 CRUD、批量导入、封面设置、排序 |
| 评论管理 | 全站评论列表、删除、屏蔽用户 |
| 聊天管理 | 房间管理、消息检索、撤回、禁言、敏感词库 |
| 村史时间轴 | 节点 CRUD、拖拽排序 |
| 运维 | 存储用量、清理孤文件、导出数据（JSON/CSV）、操作审计日志 |

### 数据导出（重要）

拆迁纪念站的最终归宿是"数字遗产"。必须提供**一键全量导出**：Markdown + 原始媒体文件 + 数据库 JSON，打包成 zip，可自行保存到网盘或刻盘。

**必须有（P0，MVP）**

3. 照片上传（批量）、相册、灯箱浏览
4. 文章/短文发布与浏览（富文本）
5. 点赞 / 收藏 / 评论
6. 村民与家庭 CRUD + 名片页
7. 聊天室（大厅）+ 图片/文件消息 + 私聊
8. 管理后台基础（用户审核、内容管理、站点配置）
9. PWA 可安装 + 响应式
10. 全量数据导出

**应该有（P1）**
家庭树、村史时间轴、通知中心、敏感词与举报、视频 HLS 转码、深色模式、分享卡片（OG 图）

**可以有（P2）**

**暂不做（v1 之外）**
多语言、第三方登录、付费、直播

## 7. 非功能性需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首屏 LCP < 2.5s（4G）；图片默认 WebP + 懒加载 + 响应式 `srcset`；接口 P95 < 500ms |
| 容量 | 支撑 500 注册用户、50 并发在线、单日 500 张图片上传 |
| 可用性 | 目标 99%（家用/小机房级别）；每日自动备份，RPO 24h、RTO 4h |
| 兼容性 | Chrome/Edge/Safari 最近 2 个大版本；iOS 15+ / Android 9+ |
| 可访问性 | 键盘可操作、对比度 AA、图片 alt（建议强制填写照片说明） |
| 安全 | 全站 HTTPS；密码 Argon2；上传白名单 + 重命名 + 剥离 EXIF 隐私；防 XSS（富文本白名单净化）、CSRF（SameSite + 双提交）、限流 |
| 隐私 | 在世村民联系方式默认仅登录可见；支持"隐藏我的名片"；不在页面展示精确住址 |
| 适老化 | 支持字号放大（全局 100%/115%/130%）；大按钮；对比明显；聊天输入框易点 |
| SEO | 文章/相册详情 SSR 不做，但需服务端生成 OG meta（预渲染或后端 `/share/:id` 直出） |

## 8. 关键业务流程

### 8.1 注册与审核

注册入口由后台配置项 `feature.reg_mode` 控制，**默认 `open`（自助注册 + 管理员审核）**，同时保留邀请码通道。

```
                      ┌ 读取 /site/config 的 reg_mode
                      ▼
  open（默认）   → 展示注册表单，邀请码「选填」
  invite         → 展示注册表单，邀请码「必填」
  closed         → 隐藏注册入口，提示「请联系管理员 XXX」
                      │
                      ▼
  填写：昵称 + 邮箱/手机 + 密码 [+ 邀请码]
        → 绑定/新建村民档案（姓名 + 家庭，可稍后补全）
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
  邀请码标记免审核 或           进入 pending 队列
  auto_approve=true            （后台顶部红点提醒）
        │                           │
        └──────────► 审核通过 / 驳回 ◄┘
                      │
      通过 → status=active（member，可发布）
      驳回 → 站内通知 + 登录后提示「联系管理员 XXX」（配置项）
```

**pending 状态下用户能做什么**：可登录、可浏览公开内容、可完善自己的村民名片；**不能**上传、发布、评论、发聊天消息——顶部常驻提示条「你的账号正在等待审核」。

**审核入口**：后台「用户与村民 → 待审核」，支持批量通过；通过即发站内通知。

### 8.2 上传照片（含处理流水线）
```
选择文件 → 前端校验类型/大小 → 生成预览
  → POST /uploads/init 获取直传凭证（本地模式返回 upload_url）
  → 分片/整文件上传（XHR 进度）
  → 后端落盘 → 立即返回 media(status=processing) + 占位图
  → 后台任务：转 WebP/多尺寸/缩略图/EXIF → status=ready
  → WebSocket 推送 processing 完成事件 → 前端替换占位图
```

### 8.3 聊天消息收发
```
客户端 send → WS 帧 {type:"message.send", payload} → 服务端校验(权限/敏感词/频率)
  → 落库 + 分配 room_seq → 广播 {type:"message.new"} 给房间在线成员
  → 离线成员：通过 /chat/rooms/:id/messages?after_seq 拉取
```

## 9. 内容治理

- **三档审核策略**（后台可切换）：先发后审（默认，熟人社区）/ 先审后发（敏感期）/ 仅管理员发布（相册、村史）。
- 敏感词库本地维护，命中则进入待审队列，不直接拒绝（避免误伤"拆迁""祖坟"等正常词）。
- 举报入口：所有内容右下角"举报"，后台有处理队列与处理时限提示。
- 侵权与隐私：上传他人肖像需说明；提供"申请下架"入口。

## 10. 视觉与情感调性（摘要，详见 05）

- 关键词：**旧照片、石墙、炊烟、族谱、褪色的红纸**。
- 主色：暖土黄 `#B4793F` + 老照片米白 `#F5EFE4` + 墨绿点缀 `#3F5B4E`；深色模式用暖褐底而非纯黑。
- 字体：标题用衬线（思源宋体 / Noto Serif SC），正文用系统无衬线，强化"书卷气"。
- 动效克制：淡入、轻微视差、照片放大过渡，避免廉价炫技。
- **一个记忆点设计**：首页滚动到拆迁日期那一段时，页面逐渐"褪色"，并浮现一行字"这里曾经是 ___ 村"。
