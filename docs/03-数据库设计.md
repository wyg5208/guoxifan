# 03 · 数据库设计

## 1. 设计原则

- 主键统一 `TEXT` 存 **UUIDv7**（时间有序，导出/合并不撞号），字段名 `id`。
- 时间统一 `DATETIME` 存 **UTC**，命名 `created_at` / `updated_at` / `deleted_at`。
- 软删除：内容类表用 `deleted_at`；关联类表（likes/favorites）直接物理删除。
- 多态关联：`target_type + target_id`（评论、点赞、收藏、通知），配套复合索引，不做外键约束。
- 所有布尔用 `INTEGER 0/1`（SQLite 无 bool），PG 迁移时改为 `BOOLEAN`。
- 枚举用 `VARCHAR` + 应用层常量，便于加值不改表。
- 计数冗余字段以 `_count` 结尾，由 service 层在同事务内 `+1/-1`。

## 2. ER 总览

```
families 1───n villagers ───1 users(可空)
   │              │
   │              └──n villager_relations (自关联：配偶/父母/子女)
   │
   └──1──n media(家庭相册关联可选)

users 1───n posts / comments / likes / favorites / messages / notifications
users 1───n refresh_tokens

albums 1───n media
media  1───n comments/likes/favorites (多态，target_type='media')

posts  1───n comments/likes/favorites (target_type='post')
posts  n───n tags  (post_tags)

rooms  1───n room_members
rooms  1───n messages

site_settings (键值)
invite_codes / audit_logs / reports / sensitive_words / attachments
```

**实体一句话说明**

| 表 | 作用 |
| --- | --- |
| `users` | 登录账号、角色、状态 |
| `villagers` | 村民人物档案（可无账号，含已故） |
| `families` | 家庭（户），含老宅位置 |
| `villager_relations` | 村民间亲属关系 |
| `posts` | 文章 / 短文（`kind` 区分） |
| `tags` / `post_tags` | 标签 |
| `albums` | 相册 |
| `media` | 照片 / 视频条目（一条媒体一个文件组） |
| `timeline_events` | 村史时间轴节点 |
| `comments` | 评论（支持二级） |
| `likes` / `favorites` | 点赞 / 收藏（多态） |
| `rooms` / `room_members` / `messages` | 聊天室与消息 |
| `attachments` | 聊天文件、附件元数据 |
| `notifications` | 站内通知 |
| `site_settings` | 站点配置 KV |
| `refresh_tokens` | 可撤销刷新令牌 |
| `invite_codes` | 邀请码 |
| `reports` | 举报 |
| `sensitive_words` | 敏感词库 |
| `audit_logs` | 管理操作审计 |

## 4. 关键查询与索引验证

| 场景 | SQL 片段 | 命中索引 |
| --- | --- | --- |
| 首页记忆流 | `posts WHERE status='published' AND deleted_at IS NULL ORDER BY published_at DESC LIMIT 20` | `idx_posts_feed` |
| 相册内列表 | `media WHERE album_id=? ORDER BY created_at DESC` | `idx_media_album` |
| 我的收藏 | `favorites WHERE user_id=? ORDER BY created_at DESC` | `idx_fav_user` |
| 聊天拉历史 | `messages WHERE room_id=? AND seq < ? ORDER BY seq DESC LIMIT 50` | `idx_msg_room_seq` |
| 未读数 | `rooms.last_seq - room_members.last_read_seq` | 内存计算，零查询 |
| 评论楼 | `comments WHERE root_id=? ORDER BY created_at` | `idx_comments_root` |
| 村民按名搜索 | `villagers WHERE name LIKE ?` | `idx_villagers_name`（前缀匹配） |

**全文搜索（P1）**：SQLite 启用 FTS5 虚拟表 `search_index(content='')`，索引 `posts.title/summary/content_html` 与 `media.caption`、`villagers.name/intro`；用触发器或 service 层同步维护。

## 5. 数据一致性要点

1. **计数**：`like_count` 等在同事务更新；每日凌晨跑一次 `scripts/recount.py` 校正漂移。
2. **消息 seq 分配**：`UPDATE rooms SET last_seq = last_seq + 1 WHERE id=? RETURNING last_seq`（SQLite ≥ 3.35 支持 RETURNING）；并在 `room_id+seq` 上建立唯一约束兜底。
3. **软删除的关联**：内容删除后，评论/点赞保留但列表接口过滤；彻底删除时级联清理。
4. **孤文件清理**：`scripts/gc.py` 扫描 `storage_key` 不在 DB 的文件与 `status='failed'` 的媒体，离线执行（只移动不删除，进 `trash/`）。

## 6. 迁移到 PostgreSQL 的对照

| SQLite | PostgreSQL |
| --- | --- |
| `TEXT` 主键 | 同 |
| `INTEGER 0/1` | `BOOLEAN` |
| `DATETIME` | `TIMESTAMPTZ` |
| `AUTOINCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` / `BIGSERIAL` |
| 部分索引 `WHERE client_id IS NOT NULL` | 同（PG 原生支持） |
| FTS5 | `tsvector` + `pg_trgm`（中文可先用 `to_tsvector('simple', ...)` + 拼音首字母） |
| `LIKE '%x%'` | `ILIKE` / `pg_trgm` GIN 索引 |

操作步骤：
```powershell
# 1. 建空库并迁移
$env:DATABASE_URL="postgresql+psycopg://village:pwd@127.0.0.1:5432/village"
alembic upgrade head
# 2. 停机 → 导出 SQLite 数据为 JSON
python -m app.scripts.export_json --out backups\migrate.json
# 3. 导入
python -m app.scripts.import_json --in backups\migrate.json
# 4. 校验行数与抽样比对，切换 .env
```
